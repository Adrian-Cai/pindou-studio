## 微信审核版本说明

优化「我的订单」页面。待支付订单展示剩余支付时间，用户可以直接继续完成支付，也可以主动取消这笔订单。支付状态一律以服务端向微信查询的结果为准，用户取消微信收银台不会被当成失败，也不会产生重复扣费。本次为既有支付流程的体验优化，不新增个人信息收集，不新增第三方信息共享。

## 本次更新

### 我的订单

- **继续支付**：对待支付订单复用原订单重新拉起微信支付，不再新建订单。订单其实已支付时跳转支付结果页，已过期时引导重新购买。
- **取消订单**：服务端先向微信查询真实支付状态，确认未支付才关闭本地订单；查询失败时不关单，避免把已支付订单误关导致漏发权益。
- **倒计时**：待支付卡片显示剩余支付时间，用服务端下发的 `serverTime` 校准本机时钟偏差，本机时间不准也不会显示负数或提前归零。
- **状态筛选**：新增「全部 / 待支付 / 已支付 / 已关闭」切换；待支付页显示当前待支付订单数与上限。
- **超时核实态**：超过支付截止时间但服务端尚未向微信核实前，订单显示「支付状态确认中」且不展示任何支付按钮，避免用户重复付款。
- **重新购买**：已关闭订单支持一键重新购买，并预选对应套餐。

### 充值页

- 从订单页「重新购买」进入时预选对应套餐，找不到就回落第一个套餐，不打断正常购买流程。
- 待支付订单达到服务端上限（当前 5 个）时，提示原因并可直接跳转「我的订单」处理，不再只弹一个无法重试的失败框。

### 服务端配套（0.18.1）

- 新增 `POST /api/payments/:orderId/continue` 与 `POST /api/payments/:orderId/cancel`，按 `orderId` 校验归属与状态后动作，不接受查询参数。
- 微信没有主动关单接口，因此超时订单改为本地关单：订单过期、查单确认未支付且超过 `VIRTUAL_PAY_RECONCILE_CLOSE_AFTER_MS`（默认 1 小时）后置为 `closed`，释放未完成订单名额；查询失败或状态不明仍保留待核实。
- 放开迟到的已支付回调：本地已关单的订单，只要微信查单确认已付，仍会纠正为 `paid` 并发放权益。
- `GET /api/orders` 额外下发 `expiresAt`（支付截止时间）、`pendingCount`（未完成订单数）与 `serverTime`（校准倒计时）。

## 发布前置条件

1. 先部署服务端 `0.18.1` 并确认 `/health` 的 `schemaStatus` 为 `valid`。旧版本服务端不下发 `expiresAt`，小程序会自动降级为不显示倒计时——不会报错，但「继续支付 / 取消」的体验依赖新接口，必须服务端先行。
2. 确认生产环境 `VIRTUAL_PAY_RECONCILE_CLOSE_AFTER_MS` 符合预期（未配置时默认 1 小时）；它决定超时订单多久后释放名额。
3. 微信公众平台的虚拟支付道具、回调地址与事件订阅均无变更，无需重新配置。
4. 真机验收四条路径：倒计时归零后状态核实、继续支付、取消订单、重新购买。重点确认在微信收银台主动取消后订单仍在「待支付」里且可再次继续支付。
