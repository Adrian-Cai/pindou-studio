## 版本概述

主线只有一条：**让 AI 生成在混元限流下活下来**，外加一处为后续更换生图模型做的前置清理。

0.30.22 已经把混元账号维度限流码 `EXCEED_REQUEST_LIMIT` 从「立刻判死」改成退避重试，
但真机上仍然能看到任务在 1 秒内失败后弹出 `AI_SERVICE_BUSY` 卡片。原因有两层：
退避等待压在**一次 HTTP 请求里**，而小程序侧请求超时是 10s，等得越久越容易被判成网络失败；
限流又是**账号维度**的，N 个任务各自退避后继续撞，等于每个轮询请求都往墙上撞一次，
把限流窗口越拖越长，最后整批一起耗尽重试。

所以这一版换了思路：服务端撞到限流不再就地等待，而是**开启全局冷却并把任务退回排队**，
冷却期内推进不调 provider、请求立即返回；小程序端则对 `AI_SERVICE_BUSY` / `AI_TIMEOUT`
这类「等一会儿就好」的失败**自己排队重投**，不再把重试包装成一张让用户手点的卡片。

另外删除了 AI 产物底部固定裁切 12% 的逻辑——那是 0.30.10 为混元生图底部标识打的补丁，
换模型后这个硬编码比例会从「有用」变成「误裁」，先清掉。

## 本次修改说明

1. **限流改为全局冷却 + 任务停在 queued**（`49579f2`，服务端）：撞到限流即开启冷却并把任务
   退回排队（清掉半截的 provider 引用、保留 `started_at`），冷却期内推进不调 provider、
   请求立即返回，冷却结束后由下一轮轮询自然重试；单个任务累计撞墙 6 次才判失败（对外仍是
   `AI_SERVICE_BUSY` / 可重试），`started_at` 超过 15 分钟则兜底判超时。
2. **冷却随撞墙次数指数增长、60s 封顶**（`b95e1d2`，服务端）：8s → 16s → 32s → 60s。
   依据是线上实测（2026-09-25，`aijob_OXQaQOagUkQnzzoQJyt4`）两次退避 1.5s 与 3.3s **全部撞墙**，
   说明限流窗口明显长于 5s，固定 8s 很可能同样不够；封顶是为了不让用户在「排队中」无限等下去。
   新增日志 `ai_provider_rate_limited`（带 attempt / cooldownMs）便于线上核对。
3. **AI 服务繁忙不再弹失败卡片，改为自动排队重投**（`49579f2`，小程序端）：`AI_SERVICE_BUSY` /
   `AI_TIMEOUT` 原地排队重投最多两次（退避 15s / 30s），期间任务回到排队态，卡片显示
   「AI 服务繁忙，N 秒后自动重试」。重投必须清 `jobId` + **换幂等键**——沿用旧键会命中服务端
   那个已 failed 的任务，每次都拿回同一个失败结果。失败任务不扣次数，重投不会让用户多花一次。
   `AI_SERVICE_UNAVAILABLE`（provider 未配置 / 额度耗尽）不在此列：重投必然再失败，应引导去用标准模式。
4. **移除 AI 产物底部固定裁切 12% 的水印带逻辑**（`3c77d90`，小程序端）：删除
   `stripAiWatermarkBand()` 与常量 `AI_WATERMARK_BAND_RATIO`，下载产物后直接持久化原图。
   标识位置与高度绑定具体生图模型，留着固定比例在换模型后只会误裁画面。

## 用户可见变化

- **AI 生成失败卡片变少**：`AI_SERVICE_BUSY` / `AI_TIMEOUT` 不再立即弹失败卡片，
  改为卡片显示「AI 服务繁忙，N 秒后自动重试」并自动重投，最多两次后才真正判失败。
- **撞限流后任务停在排队而不是秒失败**：高峰期不再出现「提交后 1 秒就失败」。
- **AI 产物不再被裁掉底部一条**：成品图、图纸与材料清单按原始出图完整保留。
  若后续接入的生图模型仍在底部烙标识，需要按其真实规格另行处理。

## 已知限制

1. **冷却是进程内的**：多副本部署时每个副本各自冷却并发高峰仍可能撞限流，
   根治要靠提配额或分布式闸门。
2. **`AI_SERVICE_UNAVAILABLE` 仍会直接失败**：provider 未配置或额度耗尽不是「等一会儿就好」，
   重投只会让用户多等一轮，故保留失败卡片并引导使用标准模式。
3. **移除裁切后若模型仍烙标识，会被采样进图纸**：这是本次刻意接受的取舍，
   后续接入新模型时须确认其是否有显式标识、位置在哪里。
