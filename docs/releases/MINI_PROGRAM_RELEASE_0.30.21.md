## 版本概述

真机上两个 AI 任务失败，作品列表两张卡片都写「AI 生成失败，请稍后重试」。

**这句话不是任何一个具体原因，它是兜底**——真·内部错误、未登记的码、客户端兜底，四种情况最后都汇到它。
所以看到它等于什么都不知道：既不能告诉用户下一步该做什么，也没法据以定位。把这条链路拆开后，断点有四层：

1. 作品列表正文用落库的 `task.failure` 取文案，而 `aiGenerationFailure` 只认 `{ failure: {...} }` 包装与
   ApiError，**对裸对象所有码都返回 `null`**——这一层不修，后面补再多定义也照不出来。
2. 客户端有 8 个「文案表里有、失败定义里没有」的码：限流、图片过大、检测结果失效、网络、
   登录失效、返回数据异常、参数无效…… 解析不出失败对象，一律兜底。
3. 服务端 `error-contract` 没登记 `AI_PROVIDER_QUOTA_EXHAUSTED`（混元额度耗尽 / 429）与
   `AI_STORAGE_NOT_CONFIGURED`，静默兜底成 AI_GENERATION_FAILED，还附赠一个必然失败的重试按钮。
4. 同一个码在两张表里写着两句话（`AI_SERVICE_UNAVAILABLE`、`AI_INPUT_FILE_UNAVAILABLE`），
   任务页与列表页对同一件事说法不一。

修完之后：限流显示「请求过于频繁，请稍后重试」、图片过大显示「图片过大，请更换图片」、
额度耗尽显示「当前暂时无法完成 AI 生成」并引导用标准模式——而不是一律「请稍后重试」。

另一条线是入队之后的导航：原来入队成功只在首页给就地反馈（按钮成功态 + 顶部横条），
用户还要自己再去作品页找进度；现在创建完立刻进任务页，进度、失败原因、重试入口都在一处。
配套修掉「任务在后台跑完时，生成页硬把用户从当前页面拽回编辑器」。

## 本次修改说明

1. **裸 failure 对象可解析**（`c0810e0`）：`aiGenerationFailure` 增加对已经是失败形态的对象的
  解析分支（`parseFailure` 要求字段齐全，不会把普通对象误认成失败）。作品列表正文走的就是这条路径。
2. **补齐失败定义**（`0bcc37d`）：`failureDefinition` 补 8 个码，并统一两处「同码不同文案」。
3. **服务端登记内部码**（`05e5470`）：额度耗尽与存储未配置映射为「AI 生成暂时不可用」；
  未命中映射时打 `ai_failure_code_unmapped` 日志，并导出内部码清单供测试守住「新码必须登记」。
4. **动作表单一来源 + 失败留痕**（`15949a7`）：manager 的重试动作 switch 收敛到 `aiFailureAction(code)`；
  失败路径补控制台日志，带错误码 / HTTP 状态 / requestId（真机调试或 vConsole 可读）。
5. **入队即进任务页**（`081ad92`）：首页创建 AI 任务后 `navigateTo` 生成页并携带 `taskId`；
  移除顶部横条与按钮成功态，不再清空选图，不再用旧草稿覆盖首页的模式选择。
6. **后台完成不抢页面**（`75ada53`）：生成页按可见性判断是否跳转编辑器，
  且在写入本地草稿（异步）之后再复查一次。

## 已知限制

1. **两端都要更新才见效**：小程序不重新上传 = 客户端仍走旧的兜底逻辑；服务端不重新部署 =
   `error-contract` 的补登记不生效，额度耗尽仍会被兜底。
2. **限流口径不变**：每用户 10 分钟 5 次的上传 / 任务创建限流照旧，本版只是让它**说人话**
   （「请求过于频繁，请稍后重试」），不会放宽。
3. 0.30.10 的真机验收 T1–T20 仍待补跑（已挂五个版本）。

## 验收重点

| 场景 | 预期 |
| --- | --- |
| 真机 AI 生成失败（任意原因） | 作品卡片正文是**具体原因**，不再是「AI 生成失败，请稍后重试」 |
| 短时间内连续提交超过 5 次 | 显示「请求过于频繁，请稍后重试」，等窗口过去后可正常提交 |
| 选超大图提交 | 显示「图片过大，请更换图片」 |
| 生成次数为 0 时提交 | 显示「AI 生成次数不足，请购买次数」，入口是购买而不是重试 |
| 首页提交 AI 任务 | 立刻进入生成页看进度；返回首页保留选图与模式选择 |
| 任务在后台（离开生成页）跑完 | 不把用户拽回编辑器；回到生成页或作品页能看到已完成 |
| AI 生成成功 | 不受本版影响，正常进编辑器 |
