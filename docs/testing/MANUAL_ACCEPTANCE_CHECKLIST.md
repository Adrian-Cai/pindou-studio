> 用途：正式提审前**必须在真机上跑完**的两组用例。勾选-style 表格，跑一项勾一项，
> 失败的留下备注。没跑完就提审 = 把未知缺陷直接交给审核和用户。
>
> - **A 组 T1–T20**：AI 生成任务化的真机验收，源自
>   `docs/frontend/AI_GENERATION_TASK_QUEUE_PLAN.md` §12。自 0.30.10 起挂在 release 的
>   「发布前置条件」里，已连续四个版本未执行。
> - **B 组 P1–P8**：虚拟支付链路的真机/后台验收，源自
>   `docs/releases/MINI_PROGRAM_RELEASE_0.30.19.md` §验收重点。推送链路在开发者工具里
>   无法真实触发，**只能真机小额购买**。

## 执行前准备

| 项 | 要求 |
| --- | --- |
| 设备 | 至少 1 台真机；**iOS 必须单独跑一遍**（虚拟支付 iOS 另有开关：小程序简称 + 微信 8.0.68+） |
| 后端 | 对应版本已部署，`/health` 返回 200，且环境变量已配齐 |
| 联调开关 | `PAYMENT_NEW_USER_GATE_ENABLED` 保持 `true`（默认）。B 组 P7 验证它会不会误挡，测完务必保持开启 |
| 测试账号 | 准备 2 个微信号：一个新人（未买过新人套餐）、一个已买过（验证限购） |
| 旧版本 | T9 需要一台装过旧版、本地留有待迁移任务的设备；装新版前别清缓存 |

**止损约定**：A 组 **T3 / T4 / T9** 任一失败不得提审——这三条分别对应「杀 App 丢任务」
「长时间后台丢状态」「老用户升级丢数据」，出问题就是用户已付的生成次数凭空消失。
B 组 **P5 / P6** 任一失败同样不得提审，涉及真实扣款。
